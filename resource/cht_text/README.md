# resource/cht_text/ —— 民汉繁中文本池与「原版行号 → 民繁」映射

繁中民间汉化 exe（`miagete_cht_170416.exe`）运行时的**全量译文串区**，
以及按**原版日文脚本行号**归组的结果。

**定位与口径**：忠实提取的民繁原文，仅与**原版日文脚本**的行号一一对应，
**与 Steam 版内容完全无关**——提取全程不读取任何官中/Steam 数据。本补丁
现阶段不采用、不做部署；对外提供给其他开发者，供后续可能的人工翻译采纳参考。

- 机制与提取过程：`doc/extract_cn_scripts.md`（§1–§3 机制与速查，§4 查表机制，§5 全量对账）
- 提取脚本已随交付定稿删除；`tool/cht_cipher.py`（密码/LZSS 参考实现）保留

## 交付与口径

**交付是 `original/` 子目录**：纯按原版日文算出每一行对应的民繁译文，不经过任何中文对照。
依据是补丁自己的查表函数（已从模块 `.text` 反汇编还原并逐字复现）：

    key = 哈希(char 文本字段整串，含结尾的 %K%P) ^ (该字段在解码后脚本里的字节偏移)
    说话人记录（%LF<名>）走同一条哈希但不加偏移

原版 45,856 条台词里 **45,848 条**能算出表里存在的 key（99.98%），剩下 8 条是纯 ASCII
`%P` 行——补丁自己也从不查表，属设计内不覆盖。（旧口径 **45,844** 条与 45,856 条不矛盾：
普查正则要求串里含 `%K%P`，因此漏掉 8 条纯 `%P` 行和 4 条以 `%K` 收尾的行，
45,844 + 8 + 4 = 45,856。）索引表 45,981 个 key 里 **45,837 个**被台词消费、
**144 个**是 `%LF` 说话人名，**零剩余**，两侧数量对账闭合。

| 文件 | 内容 | 来源 |
|---|---|---|
| `original/{脚本名}.json` ×294 | **原版行号 → `{jp, cht, key, pos}`**；未覆盖行 `cht/key` 为 `null` 占位，保证行号连续 | 按 §4 公式对原版归档查表生成 |
| `original/mapping.tsv` | 同上摊平成 45,856 行 `stem line pos key jp cht` | 同上 |
| `original/names.tsv` | 144 个说话人名 key → 民繁名（按 key 去重）| 同上 |
| `original/unmapped.tsv` | 补丁不查表的 8 行 | 同上 |
| `_cht_key_text.tsv` | 索引表 `key → 民繁原文` 45,992 行（100% 解析）| 模块 `.rdata` 索引表 + 串区导出 |
| `_cht_index_raw.tsv` | 索引表原样 `key off` 45,992 行，表起点 0x160 | 同上 |
| `_cht_hash_table.json` | 查表函数用的 256 项 u32 表（已从模块转储固化）| 模块 `.data` 转储固化 |
| `_cht_ui_table.tsv` | 引擎界面串的 10 项「纯哈希 → 民繁」（哈希实现的正对照）| 模块 `.data` UI 小表导出 |
| `pool.tsv` | 池内译文 42,511 条（比串区少 59 条短句，见「已知缺口」）| 从内存串区导出 |

结构口径：索引表区 = `[配置串 0x0..0x160) [索引表 0x160..0x59EA0] [哨兵] [串区]`，
记录 8 字节 `<u32 key><u32 off>`，串地址 = `off + 0x160`；表 45,992 行、45,981 个不同 key
（11 处并列）、指向 42,570 条不同译文。**串序不是剧本序**，条目→剧本一律经索引表按 key 查出，
不能按位置推算。

## 已知缺口与已定性的分歧

1. **池少 59 条**：内存串区被索引表引用 42,570 条不同译文，`pool.tsv` 只有 42,511 条，
   差的是「……」这类省略号短句和几个 `%LF` 人名（共引用 788 次）。
   `original/` 直接引用串区，不受这个缺口影响。
2. **同一句日文可以有不同的民繁译法**：42,562 个不同日文串里有 **364 个**被译成 2 种以上
   中文（合计 819 种译法）。这是民汉逐行翻译自带的特性，不是映射错误——
   映射按**出现次**唯一（同一日文在不同场景/不同行各取自己的译文）。
   其中大量是同一日文假名词的不同拟声写法（`はぅぅ` → 哈嗚 / 哈嗚嗚）与称谓取舍
   （`ありがとう` → 謝謝 / 謝謝你 / 謝謝妳），属译风差异；按本项目口径不算缺陷。
3. **4 行演出控制符不同**：原版全归档只有 4 行以 `%K`（无 `%P`）收尾，民繁侧 4/4 统一在
   末尾补了 `%P`（`yozora_com_402` 206、`yozora_com_A_101` 189、`yozora_com_A_103a` 102、
   `yozora_com_B_103a` 130）。这是译方的系统性习惯，采纳这几行时要决定是否保留原版的收尾。
4. **覆盖率不等于剩余部分安全**：`original/` 把原版台词全部钉到了对应的池条目上，
   但「钉对条目」只回答"民汉这里显示的是哪句中文"，不回答"这句中文译得好不好"。
   译文质量、简繁与引号转换、行号与 Steam 版对不齐的 `*_E` 场景，都在后续工作里。

## 铁律

1. **文本一条都没改**。`original/` 里每个 `cht` 都逐字等于索引表串区的某条原文，
   简繁折叠、引号归一只用于**判断哪条对应哪条**，绝不用于改写内容。
2. **不做部署**。本目录是语料/映射，不参与 `payload/METADATA.json`、不进包。
3. 若要采纳某一行，必须先做三件事，否则会与本项目约定冲突：
   繁→简（用 `_t2s_seed.json`，但它是种子表，需人工过）、
   `「」`→`“”` 引号转换、
   **译名替换以 `NameTable.txt` 为准**（繁中 可樂娜/曉哥 ↔ 我们 来露娜/晓斗）。
4. **禁止改动 Steam 官中文本**，也**禁止读取官方简中来做匹配**：
   本目录所有对应关系只用原版日文 + 补丁自己的表推出。

## 行号坐标注意（`*_E` 场景）

`original/` 的行号是**原版 .ws2 里 0x14 记录的出现序**（每场景 0..N-1，含未覆盖行的
null 占位），与官中/部署行号无关。`.lng` 的行号跟着部署脚本走，而 Steam 版在若干脚本里
插了新的文本记录，导致插入点之后的行号整体漂移：三方计数（原版 / 部署 / `.lng`）
224 个场景一致、70 个场景不一致（全是 `*_E`）。计数一致只是「同一套坐标」的必要条件；
归一要靠 `resource/seam-diffs.json` 的 `orig_idx`/`steam_idx` 对照或语音/演出锚点。

## 与官方中文的关系（决定本目录能用来干什么）

> 这是「繁中池是独立民译」这一来历的证据。对应关系一律由**原版日文 + 运行时索引表**
> 推出，不读取官方简中。

折叠简繁 + 引号归一后与池**逐字全等**的比率：

| 中文来源 | 行数 | 比率 |
|---|---|---|
| Steam 官方简中（我们未改动的部分）| 34,693 | 3.4% |
| 简中补丁新增部署的还原场景（52 个成员）| 11,267 | 33.3% |
| 官方有、我们未部署的脚本（35 个）| 4,137 | 3.8% |

所以繁中池**不是**官方中文的繁体版，而是另一套独立翻译；它对我们有价值的地方
只在"我们自己新译的行"上。
