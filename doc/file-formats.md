# 游戏文件格式规范

## Arc 归档格式

- 自定义二进制格式
- 包含多个资源文件（脚本、图像、音频等）
- 使用 UTF-16 LE 编码的文件名

## WS2 脚本格式

### 文件概述

场景脚本文件，包含对话、跳转指令、CG 显示等。

### 关键指令

- `0x04`：调用其他脚本（call，可返回）
- `0x07`：跳转到其他脚本（jump，不返回）
- `0x33`：硬载入资源（转场/背景），缺失时会卡死
- `0x34`：显示 PNA 图层资源
- `0x66`：特效遮罩，缺失时容忍（仅画面瑕疵）

### 命名规则

格式：`XXX_{数字}{字母}_H_E.ws`

- `XXX`：标志脚本所在的游戏线路
- `{数字}{字母}`：场景顺序，对检查调用链的顺序和完备性非常有价值
  - 排序优先级：数字 > 字母
- `_H`：标志是否为 H 场景，是移植目标
- 后缀：用于判断脚本来源
  - 以 `_E` 为后缀的脚本：来自 Steam 版内容
  - 不带 `_E` 后缀的脚本：来自原版内容
  - 移植时也要遵守这个命名规则，避免调试时与真正的原版脚本混淆

### 跳转指令

**两种跳转**：
- `0x04 <SCRIPT_NAME>\x00` → call（调用子流程，可返回）
- `0x07 <SCRIPT_NAME>\x00` → jump（直接跳转，不返回）

**引用规则**：
- 脚本名使用 ASCII 大写，无扩展名
- 示例：`\x07YOZORA_SAYA_107C_E\x00`
- 后缀 `_E/_H/_H_E` 必须显式写入，否则将导致脚本出处混乱

### 跳转指令提取注意事项

❌ **错误（字符串匹配）**：
```python
if b'YOZORA_SAYA_107C_E' in data:  # 可能是注释或数据
```

✅ **正确（指令匹配）**：
```python
if b'\x07YOZORA_SAYA_107C_E\x00' in data:  # 精确匹配 jump 指令
```

### EVRET 结构

每个 `_H` 场景结尾的固定结构：

```
<field1 u32> 01 82 6e 00 00 00 <float> 00 00 <field2 u32> 07 EVRET 00 0b <gallery u16> 01 07 <next> 00
```

- `field1`（`07` 前 20 字节）和 `field2`（`07` 前 4 字节）是**绝对 u32 偏移**
- 指向 `0b <gallery> 01` 指令（`07` 后 7 字节处）
- `EVRET.ws2` 有两条出口（TITLE / NMSSCN），偏移决定分支走向
- **重要**：改名操作若在该指令前插入字节，必须同步更新偏移指针

### 差分接缝修复（Steam 差分 → 原版内容）

Steam 删减 H 场景时，把它前后的**邻居脚本**也一并改写成"没有发生过 H"的语境（删改台词、改背景与
演出）。修复方针：**整体用原版覆盖 Steam 差分，只有完全语义一致的部分才沿用 Steam**。产物以
**Steam 脚本为基底**（保留其 rot6 编码形态），成员名 = Steam 名去掉 `_E`（如 `yozora_hika_103e`），
与同名 `.lng` 成对部署；原 `*_E` 脚本在其引用者全部改指后删除（记入 `resource/removed-scripts.json`）。

**判据只有一条：是否与演出相关**；逐 opcode 的演出归属以 [`resource/present-ops.json`](../resource/present-ops.json)（`use_orig` / `keep_steam`）为准：

- 与演出相关 → 取**原版**（背景、图层透明度、立绘帧号、坐标、定时器秒数**整套**回原版，不做"原版画面 + Steam 参数"的混搭——这些参数常是 Steam 为配合它换掉的画面而**成组**调过的）
- 与演出无关 → 取 **Steam**（不看它是 Steam 新增还是原版独有：跳过已读机制 `[0x1c GetMsgSkip, 0x01 Condition, 0x02 Jump2]`、`0x11 SetTimer` 的**编码形态**、`0x0b SetFlag`（承载画廊/成就 id）等。**同一条指令可按维度拆开**：`0x11 SetTimer` = 编码形态用 Steam、秒数取值用原版）
- **凡不确定的演出处理必须主动询问，不得私自决定**（已知易错：背景被换、图层透明度被调、立绘帧号被改）

**合并规则**（按「opcode + 操作数」对齐两侧指令序列，每个 block 只取一侧）：

- `equal` → 取 Steam 字节；`replace` / `delete` → 取原版；`insert`（Steam 独有）→ 只保留"与演出无关"的 opcode
- **记录内顺序**：演出 → 语音（`0x2e`）→ 说话人前缀（`0x15`）→ 文本（`0x14`）；文本恒为记录末条
- **机制组整体保留**：跳过已读机制 `[0x1c GetMsgSkip, 0x01 Condition, 0x02 Jump2]` 与其跳转**直接引用**的指令（`Condition.a/.b`、`Jump2.a` 的目标，通常是一到两条 `0x1f StopMusic`）**作为整体从 Steam 取得**——否则目标指令被丢弃后，绝对偏移无从重定位（会留下陈旧偏移）。Steam 的排布不固定（见过 `[1c][01][1f][02][1f]`），故不能只认"三重指令紧邻 StopMusic"这一种形态
- **文本 id 重排为 `0..N-1`**（与记录顺序一致）；`.lng` 同名新建，共用句取 Steam `.lng` 对应条、差分句新译

**「差分类文本记录」的判定**：除语音/句数通道外，还有一类 **同句数、无语音句的语义改写**（把性内容
换成中性说法）——任何按语音配对的工具都看不见。差异清单必须覆盖**四个来源**（演出 / 文本记录级 /
无语音句语义 / 资源），缺一会漏改；结果落到 `resource/seam-diffs.json`；译文表按它生成
（`script/seam/pin_translations.py`）。

**说话人前缀**：差分句用**原版日文名**（`%LFひかり`），共用句保留 **Steam 的英文名**（`%LFAkito`）——
两者都必须在 `zh-CN/Rio.arc` 的 `NameTable.txt` 里可解析（英文名是官方既有键；日文名按需追加，
且**只收"日文名与官中不同形"的**，`键==值` 的恒等映射冗余）

**译文书写约定**（本项目自撰译文）：**对话用 `“”`**（与官中统一；`「」` 只出现在脚本的内嵌日文原文里）；
旁白不加引号，旁白内强调用 `“”`、**对话内**嵌套降级为 `‘’`；换行用**字面 `\n`**（反斜杠 + n）
而不是真换行符

**术语**：`アキ兄`→`晓哥哥`、`あっくん`→`晓君`、ころな 的**自称**→`人家`；注音标记（`{η:イータ}`）去掉

**长度变化后必做**：`0x02 Jump2` / `0x01 Condition` / `EVRET` 的字段都是**文件内绝对偏移** → 重定位并
回读；改动 `_H` 脚本长度后重跑 `script/tools/fix_evret_offsets.py`

**立绘 / 事件 CG 引用**：只有**真冲突**（差异层会被 `0x39` 选中）的资源才改隔离名（`ORG_` 前缀 /
9X 段位）；**误报**（差异不可见或属噪声级）、**本地化差异**（cut-in 内嵌译文）**直接用 Steam 裸名**。
逐条结论见 `resource/resource-decisions.json`

**同名冲突不能只看哈希/字节**：Steam 素材分辨率更高，等比缩放后画面可能一致；必须**读图**比对语义
**或**给出**像素差异数值**（二者取其一），并看差异区域在该场景演出中**是否可见**。判"是否可见"时
**必须做隔离名别名解析**（脚本引用的是 `ORG_`/9X 名；按裸名统计 `0x39` 帧会得 0 个 → 误判成"从不显示"）；且**没有任何 `0x39` 选帧的资源（事件 CG 一类）整份图层都会显示**，有差异即真冲突。方针是**避免误报、充分利用 Steam 高质量素材**；**差异也可能是内嵌文字的本地化**（cut-in 的带状 bbox）→ 直接用 Steam 版

**验收不变式**（`script/seam/verify_seam.py`）：`tool/ws2disasm.py` 100% tile，且

1. **演出**：每条记录的演出指令（opcode + 操作数）与原版逐项相同（隔离名改名视为预期）
2. **文本**：差分类记录的内嵌文本 == 原版
3. **形态**：差分类 `.lng` 的引号形态（对话 `“…”%K%P`、旁白不以 `“` 开头）、字面 `\n` 个数与原版一致

## 资源引用编码规则

### 字符编码

- 资源名使用 **Shift-JIS** 编码（不是 UTF-8）
- 带日文的资源名（如 `B沙夜_01L`、`Aひかり_01M`）必须用 `name.encode('shift_jis')` 处理

### 改写规则

改写资源引用必须遵循以下原则：

1. **显示指令上下文精确替换**：使用 NUL 前缀的精确模式
   ```python
   # ❌ 错误：会命中已改名的尾巴，导致双前缀
   dec.replace('B沙夜_01L', 'ORG_B沙夜_01L')
   
   # ✅ 正确：精确匹配显示指令格式
   dec.replace(b'\x00' + old_name, b'\x00' + new_name)
   ```

2. **幂等性**：脚本必须可重复运行，每次运行前检查"已满足则跳过"

3. **回读校验**：改写后必须回读验证，确认修改成功

4. **控制台输出**：Windows 控制台默认 GBK/cp936，避免使用非 ASCII 字符
   - 推荐：`[OK]`/`[!]` 等 ASCII 标记
   - 或在脚本开头加：`sys.stdout.reconfigure(encoding='utf-8')`
